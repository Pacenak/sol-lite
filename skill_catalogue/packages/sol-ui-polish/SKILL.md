## When to Use

Polish an existing UI while preserving the approved visual direction and project tokens.

## Procedure

1. Inspect the rendered target and source. Identify the user's named problem and read the project's approved tokens; do not substitute a reference brand automatically.
2. Adjust hierarchy, spacing, alignment, readability and action placement within scope. Avoid unrelated redesign or decorative effects that reduce usability.
3. Check keyboard behavior, contrast and narrow/wide layouts. Inspect a new render after editing when a preview tool exists.
4. Distinguish source edits, successful build and actual visual inspection. If no renderer is configured, report that limitation rather than claiming visual approval.

## Pitfalls

Skills do not grant permissions or tool access. Report missing prerequisites and failed checks; never manufacture execution evidence.
