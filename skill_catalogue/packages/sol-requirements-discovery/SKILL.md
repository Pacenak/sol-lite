## When to Use

Resolve requirements and acceptance criteria without inventing user decisions.

## Procedure

1. Read supplied requirements and project evidence; identify the actual user, problem, constraints and measurable outcome.
2. List decisions established by evidence and the few unresolved decisions that affect implementation. Investigate repository questions with tools before asking the user.
3. Ask a focused question about a consequential unknown; for reversible implementation details, state a reasonable assumption and continue within the request.
4. Write numbered requirements with acceptance checks and explicit exclusions. Trace subsequent edits and tests to those requirements; explain any proposed scope change.

## Pitfalls

Skills do not grant permissions or tool access. Report missing prerequisites and failed checks; never manufacture execution evidence.

## Verification

Map each claimed outcome to an observed result. Read [the acceptance rubric](references/acceptance.md) when validating this procedure.
