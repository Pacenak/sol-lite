# Acceptance rubric

- Success: supply real inputs, use native tools and check the output against the requested outcome. Record tool names and actual results.
- Missing prerequisite: remove a required tool or dependency; report unavailable with the missing item and do not claim execution.
- Failure: force a validation error; preserve its evidence and report incomplete until a subsequent relevant check succeeds.
- Scope: try an unrelated phrase and a forbidden owner/sector; this package must not become an alternate permission path.
- Evaluation: deterministic contract tests prove routing and integrity only. Live model and external service acceptance remains unverified until run.
