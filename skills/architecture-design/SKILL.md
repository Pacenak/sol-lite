# Architecture Design

## Procedure
Document components, responsibilities, interfaces, data flow, trust boundaries, persistence, failure modes, observability, and deployment constraints.

Every proposed boundary must have a reason. Every dependency must have an owner and failure behavior.


## SOL-Lite boundary
This skill provides reasoning guidance only. It does not grant filesystem, terminal, repository, network, skill-install, or application permissions. Runtime policy and explicit approvals remain authoritative.
